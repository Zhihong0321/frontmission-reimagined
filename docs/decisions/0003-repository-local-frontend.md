# ADR 0003: The player frontend is repository-local under web/chart/, with pinned provenance

- Status: Accepted (Phase B, `MIGRATION_LEDGER.md` `D-034`/`D-036`/`D-039`/`D-041`)
- Date: 2026-09-05 (promoted into ADR form by CP-E1)
- Context: The finalized frontend originally lived in a sibling repository
  (`D:\FrontMission-MapLab`). A host that silently discovers a sibling folder makes a
  broken consolidation look green (the "sibling-directory false positive" risk), and
  two trees of truth drift apart.

## Decision

The active frontend path is `web/chart/` inside this repository. The host serves only
that path; the launcher generates `world.js` only from repository-local `data/` via
the in-repo `make-world.js`, and missing or failed generation is fatal — never a
warning followed by stale output. `Program.cs`'s sibling discovery (`LocateMapLab`)
was removed with every fallback.

Provenance is pinned, not assumed: the generated `world.js` carries a stable header,
its full SHA-256 (`26063b3e...0712a`) and WORLD payload hash are checked by
`tools/verify-worldjs.ps1` on every acceptance run, and the browser smoke asserts the
served bytes. `tools/clean-clone-check.ps1` proves the whole product from a
full-history clone at a location with no sibling folder.

## Consequences

- One tree of truth; the sibling `D:\FrontMission-MapLab` is a frozen reference until
  its retirement checkpoint (Phase F), after which it is deleted.
- Generated bytes under `web/chart/` must never be hand-edited; regenerate via
  `make-world.js` and let the verifier pin them.
- A missing generator or failed generation fails loudly at launch instead of serving
  a stale world.
